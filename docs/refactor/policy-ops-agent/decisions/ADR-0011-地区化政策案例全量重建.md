# ADR-0011：地区化政策案例全量重建

> Status: Accepted
> Date: 2026-09-07
> Decision owners: Jan

## 背景

任务3、任务4分支完成后独立复审发现：地区规划不能从真实入口传递广东领取地市，单一2026快照不能安全回答2030日期；案例治理的归档SHA、精确manifest、快照重放和质量落库也不满足PRD。任务4已经把持久库从851/117/528改为452/36/528，但治理前完整dump仍存在。

继续修补现有上海转录案例会保留来源、隐私、地区和政策覆盖的不一致，也不能为广东规划提供可靠验收资产。

## 决策

1. 任务3和任务4均Reopened；任务2首期保持Accepted。
2. 执行顺序改为任务3修复→地区化案例库重建→受控持久替换，不再并行。
3. 任务3使用带生效区间的多快照发布记录，按`jurisdiction_code + as_of_date`唯一选取；缺失或重叠fail-closed。
4. 广东领取地市对外只接受经用户确认的六位地级市代码，服务端转换为规则内部规范名称。
5. 旧完整851 cases、117 showcase和500旧回归tests进入离线可恢复归档；当前剩余452/36/500在新数据就绪后单事务删除。
6. 新案例使用确定性模板，结构化输入、显式断言和快照执行共同形成期望；不使用LLM，不包含真实个人数据。
7. 用户案例只生成上海和广东；公开36条固定上海18、广东18。CN只进入内部DSL/基线，四川只进入unsupported负例。
8. 新案例数`N`由覆盖manifest确定；每个case一条地区回归test，另保留当前42条DSL示例，最终`N/36/N+42`。
9. 0015/0016历史SQL不可改写；源journal校正实际执行时间，0017 idx16/`1788796800000`与0018 idx17/`1788796860000`分别承载快照区间和案例重建Schema。
10. 本决策和开发提示词不授权持久库账本repair、migration、快照调度、删除或插入；这些动作由独立Work Item在fresh audit后请求明确授权。

## 后果

- 新案例不再依赖上海社交媒体转录或真实身份字段。
- 任务4不再以452/36/528为成功条件；历史报告只作为执行记录。
- 旧数据不会直接丢弃：必须先从治理前dump生成真实文件SHA和恢复闭环。
- 日期快照和案例生成形成前置关系，牺牲并行速度以换取政策时态正确性。
- 当前持久库在受控替换前保持452/36/528，不得重复运行旧任务4apply。

## 被否决方案

- 保留旧452条并只补质量分：无法解决广东覆盖、伪归档和真实用户数据边界。
- 任务3、任务4继续并行：案例会固化尚未修复的日期快照和领取地市缺陷。
- 用LLM批量生成期望：不可确定重放，且可能引入政策含义和隐私风险。
- 立即恢复治理前dump：会改写当前持久状态，且没有必要；先在隔离库生成完整旧归档。
