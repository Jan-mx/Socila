# ADR-0010：任务2分地区交付与任务3/4并行

> Author: Jan
> Status: Accepted
> Updated: 2026-09-07

## 背景

任务2已完成阶段E缺陷修复、持久库repair和广东新增权威事实编码，但四川医保退休年限正式文件、川人社办发〔2023〕18号及2026年度缴费基数尚未取得。继续要求四川与其他地区同时完成，会长期阻塞已具备安全边界的CN、上海和广东，以及下游案例治理和地区规划。

当前持久库仍为rules=49、params=70、rule_sets=5、policy_pack_versions=4、policy_snapshots=0。当前HEAD的fresh audit会错误重放四地区整包并规划74/116/9/8，说明广东增量物化必须先修复，不能直接apply。

## 决策

1. 任务2改为分地区交付。首期Accepted范围固定为CN、上海310000和广东440000；四川510000转为Deferred/Blocked后续任务，不阻塞首期任务2Accepted。
2. 四川现有3个draft参数和3条blocking reasons保留，不删除、不批准、不生成候选快照、不开放流量，也不得回退到上海或广东。
3. 广东整体可进入首期交付。2030年前缺少市级医保退休累计缴费年限时，复用国家R-220的`needs_agent`和`W-MI-LOCAL-YEARS-MISSING`能力级守卫；医保退休结论为空，其他可计算模块继续执行。2030年起使用省级统一男30年、女25年参数。
4. 广东失业保险金“领取地市最低工资×0.9”属于政策规则，必须在任务2实现；任务3只负责确认并传递领取地市，不重复实现政策公式。
5. 广东增量物化只写新增或变化实体：5个参数、1个失业金额规则、1个GD规则集新版本和1个GD政策包新版本。目标业务计数为50/75/6/5/528/851/117；未变化的CN、上海、四川及既有GD实体不得生成新版本。
6. 任务2首期必须为CN、上海和广东形成管理员批准且可重放的候选PolicySnapshot；四川无候选快照是显式支持状态，不是验收遗漏。
7. 任务2首期Accepted后，任务3地区感知规划与任务4案例治理并行开发。两者只共享任务2冻结的不可变快照和地区支持契约，互不作为产品前置；最终集成按任务3后任务4串行完成。
8. 任务4首期只治理现有上海案例，最终452/36/528中的36条展示案例全部绑定上海候选快照，不从正文推断为广东或四川。

## 后果

- 任务2可以在四川正式来源尚未到位时完成CN、上海、广东首期验收。
- 广东用户在2030年前仍可得到养老、缴费基数、最低工资和失业结果；只有无法由权威地市参数确定的医保退休年限进入人工确认。
- 四川规划请求必须明确返回地区未支持，直到后续Work Item独立验收。
- 任务3和任务4可以并行实现，但共享Schema与migration journal在集成阶段需要串行协调。
- 任何持久库物化、管理员批准、候选快照创建、案例删除或地区激活仍分别需要其任务规定的明确授权。

## 被否决方案

- 等待四川三项来源全部到位后再推进：阻塞时间不可预测。
- 把广东整体限制到2030年后：会错误阻止已有权威政策能力。
- 在2030年前套用省级30/25：缺乏市级过渡期依据。
- 先完成任务4再开发任务3：两者在任务2快照稳定后不存在必要产品依赖。
