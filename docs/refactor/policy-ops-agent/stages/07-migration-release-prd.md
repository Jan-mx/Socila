## 1. 背景与现状

当前应用运行于Vercel并使用Neon HTTP PostgreSQL。目标环境是单台企业内网Linux服务器，运行Next、FastAPI、Celery、Redis、PostgreSQL和MinIO。单机部署降低成本但存在主机级单点，因此迁移、离机备份、恢复和回退是上线阻断条件。

## 2. 目标

- 建立可重复、可审计的单机Docker Compose部署。
- 将Neon Schema和业务数据迁入本地PostgreSQL。
- 配置Redis、MinIO、FastAPI、Celery和LangGraph Checkpoint。
- 完成安全、容量、备份、恢复和故障演练。
- 在维护窗口整体切换，并保留明确回退路径。

## 3. 非目标

- 不建设高可用数据库、Kubernetes或多机负载均衡。
- 不在无用户授权情况下操作生产、删除Neon或轮换真实密钥。
- 不在本阶段继续增加产品功能。

## 4. 用户故事

- **REL-US-001** 作为运维人员，我能从空服务器和离机备份恢复全部服务。
- **REL-US-002** 作为管理员，我能确认迁移前后规则、用户、会话、方案和发布数据一致。
- **REL-US-003** 作为用户，我在切换后获得与迁移前一致的规划结果。
- **REL-US-004** 作为负责人，我能在阻断问题出现时恢复旧版本和Neon只读数据。

## 5. 功能与运维需求

- **REL-FR-001** Compose固定服务版本、网络、健康检查、资源限制和restart策略。
- **REL-FR-002** 只有反向代理对企业网络开放；数据库、Redis、MinIO和FastAPI仅内部可达。
- **REL-FR-003** Secret从部署环境或受限文件加载，不进入镜像和Git。
- **REL-FR-004** PostgreSQL使用独立Core、Agent和Checkpoint角色及Schema。
- **REL-FR-005** 迁移通过版本化migration创建目标Schema后再导入数据。
- **REL-FR-006** 导入后校验记录数、主键、序列、哈希、JSONB、UUID、日期和引用完整性。
- **REL-FR-007** PostgreSQL基础备份、WAL和MinIO对象备份写到另一物理设备/NAS。
- **REL-FR-008** 记录RPO、RTO、备份保留、加密和恢复负责人。
- **REL-FR-009** 提供应用、数据库、队列、对象存储和外部API健康监控。
- **REL-FR-010** 切换前冻结写入并记录一致性时间点。
- **REL-FR-011** 切换失败可以恢复旧应用和Neon只读连接。
- **REL-FR-012** 回退窗口结束前不删除Neon项目和导出备份。

## 6. 单机部署设计

服务：reverse-proxy、next-core、fastapi、celery-worker、celery-beat、postgres-pgvector、redis、minio。

- 使用内部网络分隔入口与数据服务。
- 为Next、FastAPI和Worker设置CPU/内存限制，避免OCR或Embedding任务拖垮数据库。
- PostgreSQL、Redis和MinIO使用持久卷；数据库数据目录不与临时构建目录混用。
- 健康检查区分进程存活和依赖就绪；反向代理只转发ready实例。
- 系统日志轮转并过滤密钥、个人资料和完整文档。

## 7. Neon迁移流程

### 7.1 演练

1. 创建空本地数据库并执行全部migration。
2. 从Neon一致性导出Schema相关数据和业务表。
3. 按外键依赖导入并修复序列。
4. 运行结构、数量、哈希、引用和业务对账。
5. 运行112个测试、黄金规划、后台冒烟和历史政策回放。
6. 记录总耗时、停写估算、失败和修复。

至少完整重复两次，第二次不得依赖人工临时修复。

### 7.2 正式切换

1. 用户批准维护窗口和回退条件。
2. 冻结写入，记录时间点并执行最终导出。
3. 导入本地PostgreSQL并执行自动对账。
4. 启动内部全栈，执行阻断冒烟。
5. 切换内网入口并监控错误、延迟和数据库。
6. Neon改为只读回退来源，保持约定窗口。

## 8. 备份与恢复

- 每日逻辑备份用于跨版本和选择性恢复。
- 基础备份加WAL用于时间点恢复。
- MinIO执行版本化和离机增量同步。
- Redis视为可重建队列，不作为唯一业务事实源；必要任务状态写PostgreSQL。
- Checkpoint随PostgreSQL备份恢复，并验证workflowVersion兼容性。
- 每月执行恢复演练，至少每季度执行空服务器全栈恢复。

## 9. 容量与性能

- 使用代表性100名用户、并发规划、后台查询和采集任务测试。
- OCR、批量Embedding和HNSW构建使用低优先队列和维护窗口。
- 监控PostgreSQL连接、慢查询、缓存命中、磁盘、WAL和表膨胀。
- 监控Redis内存、队列深度、任务时长和死信。
- 预留数据库和MinIO增长空间；达到阈值前告警而非自动扩容。

## 10. 安全

- 主机仅开放必要管理和HTTPS端口，管理访问限制到内网/VPN。
- 容器非root运行（镜像支持时），镜像固定digest并执行漏洞扫描。
- PostgreSQL不对主机公网接口监听，数据库角色最小权限。
- 备份加密，密钥与备份分离保存。
- 执行依赖和Secret扫描，确保镜像层和日志中无密钥。
- 生产个人数据不得用于外部模型测试。

## 11. 可观测与告警

- 应用5xx、P95延迟、SSE中断、登录失败和越权拒绝。
- PostgreSQL连接、锁、慢查询、磁盘和备份状态。
- Celery队列、重试、死信和Beat漂移。
- Agent节点失败、等待审核、模型429/503和Token。
- MinIO容量、对象错误和备份同步延迟。

## 12. 交付物

- 生产Compose、环境模板和运维Runbook。
- Neon导出、本地导入和自动对账工具。
- 两次迁移演练报告。
- 备份、恢复、容量、安全和回退报告。
- 维护窗口与生产切换清单。
- 最终架构、技术栈、进度和验收文档。

## 14. 验收场景

- **REL-AC-001** Given空服务器，When使用Runbook和离机备份，Then恢复可登录、可规划、可审核的系统。
- **REL-AC-002** Given两次独立迁移演练，When比较结果，Then记录数、哈希和黄金输出一致。
- **REL-AC-003** Given任一数据服务端口，When从非授权网络访问，Then连接被拒绝。
- **REL-AC-004** GivenOCR和批量索引运行，When用户执行规划，Then服务不发生资源耗尽。
- **REL-AC-005** Given正式切换冒烟失败，When触发回退，Then在约定RTO内恢复旧入口。
- **REL-AC-006** Given主机永久损坏，When从离机备份恢复，Then达到已批准RPO。
- **REL-AC-007** Given回退窗口尚未结束，When检查Neon，Then数据保持只读可用且未删除。

## 15. 生产停止条件

- 用户未明确批准维护窗口或生产写冻结。
- 任一演练仍需未文档化的人工修复。
- 黄金结果、数据哈希、权限、安全或恢复测试失败。
- 备份仍保存在同一物理主机。
- 生产密钥出现在Git、镜像或日志。

## 16. Definition of Done

- REL-FR-001～012全部实现并有证据。
- REL-AC-001～007全部通过。
- 两次迁移演练、空机恢复和回退演练完成。
- 用户显式授权后完成正式切换；若未授权，阶段保持ready-to-release而非伪报完成。
- architecture、tech-stack、implementation-plan和progress反映生产真实状态。
- 创建 `build: 完成内网单机部署与迁移验收` 提交并推送阶段分支。
