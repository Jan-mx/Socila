# 阶段 NN：名称 PRD

## 文档元数据

| 字段 | 值 |
| --- | --- |
| 阶段 | NN / English Name |
| 状态 | Draft / Ready / In progress / Accepted |
| 前置依赖 | 明确阶段、接口和数据 |
| 可并行阶段 | 无或具体阶段 |
| 后续消费者 | 具体阶段 |
| 退出门禁 | 可验证的一句话 |
| 对应总体需求 | PRD-FR/NFR编号 |

## 1. 背景与现状

说明当前实现、问题、证据和不处理的影响。

## 2. 目标

列出本阶段必须实现的结果。

## 3. 非目标

列出明确不做的内容，防止范围扩张。

## 4. 用户故事

- **XXX-US-001** 作为...我需要...从而...

## 5. 功能与工程需求

- **XXX-FR-001** 使用可测试、无歧义的语言描述。

## 6. 实现设计

描述模块职责、依赖方向、数据流、状态机和关键算法。

## 7. 数据模型与不变量

列出实体、重要字段、唯一约束、状态和不可变规则。

## 8. API、事件与类型

列出入口、请求/响应、错误、幂等、权限和版本兼容。

## 9. 迁移与兼容

描述已有数据、旧接口、双读/双写、切换和清理时点。

## 10. 安全、隐私与可观测

描述信任边界、敏感数据、权限、日志、指标和告警。

## 11. 失败模式、重试与回退

明确可重试/不可重试、降级、幂等、停止和回退条件。

## 12. 交付物

列出代码、migration、接口、页面、测试、报告和Runbook。

## 15. Definition of Done

- 所有需求有实现与测试映射。
- 所有验收场景有新鲜证据。
- architecture、implementation-plan和progress同步。
- 阶段提交和推送完成。
