# ADR-0001：单分支串行执行模型

- 状态：Accepted
- 日期：2026-08-30
- 决策者：用户（Jan-mx）与 Goal Agent 共同确认
- 影响阶段：Stage 01～07 全部

## 背景

`parallel-development-plan.md` 为 4～6 人并行开发设计，规定每阶段创建独立工作树与 `stage/*` 分支，验收后由集成 Agent 按序合入重构分支。本次重构由单个 Goal Agent 串行执行全部阶段，无并行写入方。用户于 2026-08-30 明确指示：直接在 `refactor/policy-ops-agent-platform` 分支上按开发步骤开发，每阶段测试成功后再进行下一阶段。

## 决策

- 不创建 `stage/*` 分支与独立工作树；全部阶段直接在 `refactor/policy-ops-agent-platform` 分支串行开发。
- 每阶段验收（DoD + 验收报告 + 敏感扫描）全部通过后，创建一次提交（`英文行为: 中文简短总结`，提交信息采用各阶段 PRD 预写文案）并推送到 `origin/refactor/policy-ops-agent-platform`，然后才进入下一阶段。
- 不创建 PR、不合并 `main`；每阶段提交即回退点。

## 备选方案

| 方案 | 优点 | 缺点 | 未选择原因 |
| --- | --- | --- | --- |
| 按 parallel plan 建 stage 分支+独立工作树 | 隔离彻底、天然支持并行 | 单代理串行下每个工作树需独立安装依赖、合并成本高、无并行收益 | 执行模型为单代理串行，隔离收益为零 |
| 直接在 main 上开发 | 少一层分支管理 | 违反仓库规则（重构须在专用分支进行），main 失去稳定参照 | 不符合 AGENTS.md 约束 |

## 后果

- 正面影响：省去每阶段工作树安装与合并开销；提交历史线性清晰；progress/architecture 更新即时生效，无跨工作树同步延迟。
- 负面影响：失去阶段分支级隔离，回退粒度为"每阶段一个提交"；若中途需要实验性改动，需临时开分支处理。
- 新增约束：阶段验收必须在阶段提交前完成全部验证（提交即门禁）；progress.md 的"当前步骤"必须始终与工作树实际状态一致，便于中途恢复。

## 验证与复审触发条件

验证：每阶段提交推送后，`git log --oneline origin/refactor/policy-ops-agent-platform` 应显示恰好一个该阶段的阶段提交，且工作树干净。

复审触发：恢复多人/多代理并行开发；出现需要长周期跨阶段实验的需求；某阶段验证需要与主线状态隔离的破坏性操作。任一发生时重新评估并升级为 stage 分支模型（以新 ADR 取代本决策）。
