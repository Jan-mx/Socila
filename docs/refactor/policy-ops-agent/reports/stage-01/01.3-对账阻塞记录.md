## 方向判断（漂移成因假设）

- 当前代码全量检索不引用 `showcase_cases.transcript_text`；`transcript_text` 在当前 schema.ts 中属于 `cases` 表（案例转写文本）。
- 判断：Neon 线上库由**旧版 Schema** 建立；schema.ts 修订（transcript_text 移至 cases、showcase_cases 约束放宽/默认值调整）后**未对线上执行 push**。仓库历史经历重置（schema.ts 仅 1 个 init 提交），无法从提交史进一步佐证。
- 声明式 `src/lib/db/schema.ts` 为权威结构源（PRD 6.2），线上库为滞后的物理状态。

## 处理决定（不自动修复）

1. 本阶段不修改 Neon、不修改 schema.ts 迁就线上状态；空库迁移基线保持按声明式 Schema 生成。
2. 需要一次**显式 migration**（建议在 Stage 02 migration/写路径工作，或 Stage 07 迁移演练前）决定并处理：
   - 线上 `showcase_cases.transcript_text` 的存量数据是否有保留价值 → 决定 DROP 或补回声明式定义；
   - NOT NULL / UNIQUE / default 差异是否对齐（对齐前需数据校验，防止存量数据违反新约束）。
3. 对 Neon 的任何修复都是对现有库的写操作，统一留待 Stage 07 迁移演练路径处理；不影响本地演练库与空库重建路径。
4. Neon server 为 PostgreSQL 18.6，与 tech-stack 目标 17 不同——Stage 07 迁移目标库版本选择时需复核（升级演练容器或下调目标），仅信息记录，不阻塞。
