## 2. 契约内容

- **ApiError** `{ code, message, requestId, details? }`：10 个稳定业务码与 HTTP 状态一一固定映射——`BAD_REQUEST`/400、`UNAUTHORIZED`/401、`FORBIDDEN`/403、`NOT_FOUND`/404、`CONFLICT`/409、`PAYLOAD_TOO_LARGE`/413、`VALIDATION_FAILED`/422、`RATE_LIMITED`/429、`INTERNAL_ERROR`/500、`SERVICE_UNAVAILABLE`/503。
- **RequestContext** `{ requestId, actorId?, role?, sessionId?, source }`：requestId 取 `X-Request-Id`（缺省生成 UUID）并回写响应头；role ∈ user/admin/agent（与 design-document 三类角色对齐）；source ∈ web/service/agent；身份由 auth 层传入，不接受客户端伪造。
- **IdempotencyMetadata** `{ key, operation, createdAt }`：写接口以 `Idempotency-Key` 头声明；重复语义固定为 `first-result-or-409`（FND-AC-005）——相同键重复提交要么返回首次结果、要么 409 CONFLICT，禁止部分执行或重复副作用。
- **版本与兼容**（写入 architecture.md）：公开 API 破坏性变更须引入 `/api/v2/...` 新前缀并保留过渡期；内部服务接口固定 `/api/internal/v1/...` + `X-Service-Name` 服务身份头，不接受浏览器 Cookie 作唯一认证；OpenAPI 由 Zod Schema 派生（生成流程在阶段04建立）。
- 契约模块保持框架无关（不导入 `next/server`），为阶段02领域边界（CORE-FR-003）铺路。

## 3. 范围控制

- 阶段01只固定约定，**不迁移存量接口**（PRD §7）。存量路由的 `{ error }` 旧形态（如 `/api/chat` 的 413/400）在阶段02模块化时逐域替换，避免本阶段改变 API 业务语义。
- 契约快照以"约定 + 样本测试"形式固化；全量 OpenAPI 派生属阶段04。
