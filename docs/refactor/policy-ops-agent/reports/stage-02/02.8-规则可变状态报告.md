## 1. 问题定位

`golden.test.ts` 注释记载的历史污染源经定位确认：`runTestCase` 单规则路径构建的 ctx 直接引用调用方对象——`calc`/`user` 按引用传入，`params` 仅浅拷贝（内嵌表行数组与 baseParams 共享引用）。规则动作经 `setDeep` 直写 ctx，跨调用复用同一输入对象时会穿透污染并造成结果漂移。全量路径（orchestrateInMemory）已有 structuredClone，规则定义本身无写入位点（grep 验证）。

## 2. 修复

`src/lib/engine/test-runner.ts` `runTestCase`：输入深度隔离——
- `structuredClone(baseParams)` 后再并入 `input.params`/`params_override`（保持顶层覆盖语义，消除嵌套共享）；
- `input` 各字段（user/calc/plan 等）逐项 `structuredClone`。

## 3. 验证（`src/lib/engine/__tests__/input-isolation.test.ts`，4 项）

1. 同一输入对象连跑两次全量编排：plan/calc 深比较一致，输入与 params JSON 快照不变；
2. **同一组 rule/param 对象连跑两轮完整 28 条语料**（历史污染场景）：规范化输出零漂移；
3. 同一 TestCase 对象跨两次 runTestCase：actual 一致、testCase.input 未被修改；
4. 修复后完整输出仍与 01.2 提交的黄金快照一致（无行为变化、已知偏差集合不变）。
