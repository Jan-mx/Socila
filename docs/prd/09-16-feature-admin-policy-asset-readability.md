# 后台政策资产中文可读化 Feature PRD

> Author: Jan
> Status: Active
> Updated: 2026-09-16

## 1. 文档元数据

| 字段 | 值 |
| --- | --- |
| Feature | 后台政策资产中文可读化 |
| 需求标识 | APR（Admin Policy Readability） |
| 影响范围 | 后台规则管理、规则集、参数管理、发布中心 |
| 当前阶段 | 需求定稿，等待用户人工验收 |

本文定义后台政策资产的中文可读化改造。规则、参数和规则集继续使用稳定编号作为业务身份，后台页面以中文名称作为主要展示内容。

本文只定义需求、接口、数据变化和验收条件，不记录执行结果、提交历史或测试通过声明。

## 2. 背景与问题

### 2.1 当前模块职责

| 模块 | 职责 | 当前业务身份 |
| --- | --- | --- |
| 规则管理 | 管理单条判断、计算和输出逻辑 | `rule_id` |
| 规则集 | 管理参与计算的规则及其执行顺序 | `rule_set_id`及有序`rule_id[]` |
| 参数管理 | 管理规则引用的政策数值、表格和时间线 | `param_id` |

发布中心统一管理上述三类政策资产的草稿、预发布和生产状态。

### 2.2 当前问题

- 规则管理页面内存在“规则集”标签页，侧边栏又存在独立规则集入口，功能和代码重复。
- 独立规则集页面只显示规则编号，管理员需要依靠记忆判断每条规则的含义。
- 规则集新增成员依赖手工输入编号，容易输入错误或加入错误地区的规则。
- 参数没有正式中文名称和说明字段，页面主要显示参数编号。
- 发布中心将规则、参数和规则集混排在同一阶段，且主要显示编号，难以快速辨认资产类型和用途。
- 发布历史只显示实体类型和编号，缺少对应版本的中文名称。
- 中文展示不足导致管理员容易把编号误认为实际业务内容。

### 2.3 规则集顺序的业务意义

规则引擎按规则集保存的 `rule_id[]` 顺序执行规则。前序规则产生的用户标准化数据和计算结果可能被后序规则读取。

```text
输入标准化
  → 资格与政策口径判断
  → 退休、养老、医保和失业计算
  → 方案生成
  → 最终门禁
```

因此规则集顺序属于可执行业务配置，不是单纯展示排序。中文名称只能用于显示，不得替换编号、改变顺序或触发自动排序。

## 3. 目标与非目标

### 3.1 目标

1. 规则集按执行顺序显示规则中文名称。
2. 稳定编号作为辅助信息继续保留。
3. 删除规则管理中的重复规则集标签页。
4. 保持规则管理现有列表和详情展示不变。
5. 为规则集和参数增加正式中文名称。
6. 参数管理以中文名称作为主要展示内容。
7. 发布中心在统一流水线中按资产类型分类。
8. 发布中心和发布历史显示对应实体版本的中文名称。
9. 保持地区、版本、发布、审计和规则执行语义不变。

### 3.2 非目标

- 不修改规则管理列表和规则详情页的整体样式。
- 不为规则新增摘要字段。
- 不以中文名称替代任何稳定编号。
- 不修改规则DSL、决策表、输入输出或计算逻辑。
- 不自动重排规则集成员。
- 不改变发布状态机、发布门禁或回滚语义。
- 不改变地区继承、overlay、快照或历史重放语义。
- 不在本Feature中执行生产迁移、生产物化或生产部署。
- 不创建PR、不合并主分支、不创建Tag或Release。

## 4. 目标用户与使用场景

### 4.1 目标用户

- 维护规则和政策参数的后台管理员；
- 审核草稿、预发布和生产资产的发布人员；
- 排查规则集顺序和地区覆盖关系的开发或运营人员；
- 查看历史发布记录的审计人员。

### 4.2 用户故事

- 作为管理员，我希望在规则集中直接看到规则中文名称，不需要记忆编号。
- 作为管理员，我希望中文名称显示后，规则原有执行顺序保持不变。
- 作为管理员，我希望搜索规则名称后将其加入规则集，而不是手工输入编号。
- 作为参数维护人员，我希望看到“上海市最低工资标准”，同时保留 `P-SH-MIN-WAGE`。
- 作为发布人员，我希望同一发布阶段内的规则集、规则和参数分组展示。
- 作为审计人员，我希望发布历史显示当时实体版本的中文名称，而不是使用当前版本名称冒充历史名称。

## 5. 目标信息架构

### 5.1 侧边栏

保留规则管理、规则集、参数管理和发布中心四个独立入口。规则管理页面内部不再出现规则集标签页。

### 5.2 规则集成员

规则集成员按原执行顺序显示中文名称、稳定编号、来源地区和版本。中文名称来自规则现有 `name` 字段，不新增或自动生成摘要。

### 5.3 参数

参数以中文名称为主标题，编号、地区和版本为辅助信息，并继续展示当前值、单位和生效日期。

### 5.4 发布中心

继续保留“草稿 → 预发布 → 生产”统一发布流水线。每个阶段内部依次分为规则集、规则和参数，各分组可折叠并显示数量。

## 6. 功能需求

### APR-FR-001 删除重复规则集入口

规则管理页面必须删除内部规则集标签页、重复请求、编辑状态和相关组件。侧边栏独立规则集页面必须作为唯一规则集管理入口。

### APR-FR-002 保持规则管理展示不变

除删除重复标签页和调整页面说明外，规则管理现有表格、搜索、筛选、行跳转以及规则详情编辑、校验、晋级和示例执行必须保持不变。

### APR-FR-003 规则集正式中文名称

规则集实体必须新增必填、简短、稳定的 `name`；`description`继续保存详细说明。现有国家、上海、广东和四川规则集必须补齐人工中文名称。规则集编号继续作为业务身份。

### APR-FR-004 规则集成员中文显示

规则集成员必须以规则现有 `name` 为主要内容，并同时显示顺序号、规则编号、实际来源地区、解析版本和状态。规则名称缺失时显示编号，并标记名称不可用。

### APR-FR-005 保持规则执行顺序

页面展示顺序必须与规则集持久化的 `rule_id[]` 完全一致。系统不得按中文名称、编号或模块排序，不得因异步名称加载重排，也不得将中文名称写入成员数组。调整顺序前必须提示该操作会影响计算结果。

### APR-FR-006 规则集精确身份

规则集读取和更新必须使用 `rule_set_id + jurisdiction_code + version`。缺少地区或版本时返回明确错误，不得跨地区猜测。

### APR-FR-007 规则集成员解析

成员必须按规则集地区继承链、有效期和overlay语义解析，保持原数组位置并返回实际来源地区和版本；支持国家基线继承以及地区新增、替换、限制和豁免；拒绝无关地区同编号规则；无法解析时标记 `missing`。管理端默认使用服务器当前日期并明确展示解析日期，接口允许合法 `as_of_date`。历史精确执行内容仍以不可变快照为准。

### APR-FR-008 规则集成员展开

成员支持表格内展开，只读显示说明和备注、输入、决策条件和动作、输出、参数引用、证据以及完整详情入口。无法友好渲染的DSL节点使用格式化JSON回退。

### APR-FR-009 规则选择器

新增成员使用支持名称和编号搜索的选择器，显示名称、编号、地区、版本和状态，排除已加入成员以及不属于目标继承链、无法解析或不可用的规则，最终保存稳定编号。

### APR-FR-010 参数中文名称和说明

参数实体必须新增必填 `name` 和可选 `description`。现有 `note`继续用于版本、兼容或维护备注，不得代替正式名称。

### APR-FR-011 参数数据补全

国家、上海、广东和四川当前DSL参数必须逐项补齐人工编写的名称和说明，不得仅通过拆分英文编号自动生成中文名称。

### APR-FR-012 参数管理展示

参数管理以中文名称为主、编号为辅，显示值、单位、地区、版本、状态和有效期；展开显示说明、表格或时间线、来源、证据、overlay操作以及引用规则。编辑、校验和API定位继续使用参数编号。

### APR-FR-013 发布中心统一治理

发布中心继续统一管理规则集、规则和参数，不拆分为三个发布系统。

### APR-FR-014 发布阶段内分类

草稿、预发布和生产阶段内依次建立规则集、规则和参数三个可折叠分组。阶段显示总数，分类显示分类数量；空分类使用简洁空状态。

### APR-FR-015 发布实体中文名称

发布卡片以中文名称为主：规则使用 `rule.name`，参数使用 `param.name`，规则集使用 `rule_set.name`；同时显示编号、地区、版本和状态。晋级和回滚继续使用实体类型、地区、编号和版本。

### APR-FR-016 发布历史名称

发布历史依据 `entity_type + jurisdiction_code + entity_id + entity_version`解析名称，不得以当前名称冒充历史名称。旧记录缺少身份或对应实体不存在时保留编号、显示名称不可用且不得猜测。

### APR-FR-017 历史数据兼容

数据库升级允许旧数据暂时以编号作为名称回退。所有新建、重新导入或重新物化的规则集和参数必须提供正式名称；兼容回退不得阻止读取，但校验必须识别未补全状态。

## 7. 数据模型

规则模型不变，继续使用 `ruleId` 和 `name`。规则集新增 `name: string`。参数新增 `name: string` 和 `description: string | null`。

兼容迁移必须新增上述字段，为无法确定名称的旧行临时使用实体编号，对当前版本化DSL资产使用人工名称补全，并在新建和物化入口强制名称非空；不得修改编号、政策值、规则顺序或状态。生产迁移和持久数据补全不属于代码实施的默认授权范围。

## 8. API契约

```ts
interface RuleSetMemberView {
  position: number;
  ruleId: string;
  name: string | null;
  jurisdictionCode: string | null;
  version: number | null;
  status: string | null;
  operation: string | null;
  missing: boolean;
}

interface PipelineEntity {
  entityType: "rule_set" | "rule" | "param";
  entityId: string;
  displayName: string | null;
  jurisdictionCode: string | null;
  version: number;
  status: string;
  updatedAt: string;
}
```

规则集详情必须同时返回原始 `rules` 和解析后的 `members`；详情与更新携带 `jurisdiction_code`和`version`，成员解析可携带 `as_of_date`，缺省为服务器当前日期。规则集成员和发布名称必须批量读取，不得产生逐成员或逐卡片查询。

## 9. 权限与安全

- 所有后台接口继续要求管理员身份。
- 草稿、预发布、生产和回滚权限保持不变。
- 中文名称不得参与权限判断。
- 编辑白名单允许规则集和参数名称字段，但继续拒绝地区、版本、状态等受控字段。
- 名称和说明不得包含未经转义的HTML。
- 发布历史编号和版本不得被名称更新覆盖。

## 10. 非功能需求

- **APR-NFR-001 确定性**：相同规则集身份、地区链和日期必须得到相同顺序和名称解析结果。
- **APR-NFR-002 性能**：成员和发布名称采用批量查询；折叠内容可延迟加载，但名称随列表一次返回。
- **APR-NFR-003 可访问性**：折叠和展开支持键盘操作，按钮具有辅助标签，错误状态不只依赖颜色。
- **APR-NFR-004 兼容性**：展示字段不得改变规则引擎、快照、发布、回滚或重放结果。
- **APR-NFR-005 审计真实性**：历史名称无法精确解析时显示不可用，不得采用当前名称推断。

## 11. 失败模式

| 场景 | 目标行为 |
| --- | --- |
| 规则成员存在且可解析 | 显示中文名称、编号、来源地区和版本 |
| 规则成员编号不存在 | 保留原顺序，显示编号和“规则不存在” |
| 同编号存在多个地区版本 | 按地区链、日期和版本精确解析 |
| 规则名称为空 | 显示编号并标记名称不可用 |
| 规则集或参数名称为迁移回退编号 | 正常读取并标记名称待补充 |
| 发布实体名称加载失败 | 卡片仍可通过编号完成受控操作 |
| 发布历史实体已删除 | 显示历史编号和名称不可用 |
| 名称与编号搜索同时命中 | 按稳定实体身份去重 |
| 保存规则集包含重复或缺失成员 | 拒绝保存并指出问题编号 |
| 名称加载顺序变化 | 不得影响成员显示或执行顺序 |

## 12. 实施顺序

1. 从APR需求和验收场景派生最小测试。
2. 删除规则管理中的重复规则集标签页并验证原页面无变化。
3. 增加规则集和参数名称字段及DSL契约。
4. 补齐当前版本化资产的人工中文名称。
5. 实现规则集精确身份和成员批量解析。
6. 改造独立规则集页面的名称展示、展开和搜索选择器。
7. 改造参数管理页面的名称及关联展示。
8. 扩展发布流水线和历史接口的名称解析。
9. 将发布阶段内部按规则集、规则和参数分组。
10. 完成迁移、兼容和回归验证。
11. 同步架构、测试、追踪和进度文档。
12. 独立复审通过后再请求生产迁移或部署授权。

## 14. 验收场景

- **APR-AC-001 单一规则集入口**：规则管理只显示现有规则列表，侧边栏独立规则集入口正常。
- **APR-AC-002 规则管理无视觉回归**：列表、搜索、筛选、行点击和详情页与改造前一致。
- **APR-AC-003 规则集中文名称**：任一规则集按原顺序显示中文规则名称，编号为辅助信息。
- **APR-AC-004 顺序不变**：名称解析前后，成员数组、页面顺序、快照顺序和执行轨迹一致。
- **APR-AC-005 地区解析正确**：国家继承和地区新增/覆盖来源正确，不串区。
- **APR-AC-006 缺失成员可见**：缺失成员保留原位置并禁止保存。
- **APR-AC-007 名称搜索添加规则**：中文名称和编号均可搜索，保存值仍为规则编号。
- **APR-AC-008 参数中文显示**：显示名称、编号、值、单位、地区、版本和有效期，并可查看说明、来源和引用规则。
- **APR-AC-009 发布阶段分类**：三个阶段内部均按规则集、规则和参数分组，数量对账一致。
- **APR-AC-010 发布操作身份稳定**：卡片显示中文名称，操作仍使用实体类型、地区、编号和版本。
- **APR-AC-011 发布历史真实性**：精确版本显示当时名称；无法解析时显示编号和名称不可用。
- **APR-AC-012 完整门禁**：目标测试、模块测试、数据库测试、TypeScript、ESLint、Build、适用E2E和差异检查全部通过，不降低规则或门禁。

## 16. Definition of Done

- APR功能、非功能需求和验收场景均有实现与新鲜证据。
- 规则管理只删除重复入口，原展示无回归。
- 规则集成员按原顺序显示中文规则名称。
- 规则集和参数具有正式中文名称。
