# LLM 自主工具路由与对话回答恢复 Feature PRD

> Author: Jan
> Status: Active
> Updated: 2026-09-15

## 1. 文档元数据

| 字段 | 值 |
| --- | --- |
| Feature | LLM 自主工具路由与对话回答恢复 |
| 需求标识 | ATR（Autonomous Tool Routing） |
| 影响范围 | Web 对话 Agent 的系统提示词、工具选择与流式输出编排 |
| 关联能力 | `searchPolicy`、`computePlan`、`validateField`、`updateProfile` |
| 当前阶段 | 本地门禁、独立复审和本机生产Web人工UAT通过；等待PR六项CI与main squash合并 |

本文定义对话 Agent 从“服务端正则决定检索与回答放行”调整为“LLM 根据系统提示词自主选择工具”的目标行为。本文只定义需求、边界、修复方案和验收条件，不记录执行日志、测试结果或提交历史。

## 2. 背景与问题证据

### 2.1 当前问答链路

当前链路为：

```text
Chat API
  → 用户鉴权、请求校验、会话读取与确认地区注入
  → UI 消息转换为模型消息
  → 拼接 SYSTEM_PROMPT、用户画像、未决问题和服务器日期
  → 注册 computePlan、validateField、updateProfile、searchPolicy
  → 服务端正则判断用户是否询问政策事实
  → 命中时通过 prepareStep 强制首步调用 searchPolicy
  → LLM 执行工具循环并生成文本
  → 服务端缓存完整文本并再次以正则判断是否包含政策事实
  → 校验 searchPolicy 命中及最终文本中的官网/归档链接
  → 无合格来源时将完整回答替换为固定兜底语
  → 流式返回并持久化会话
```

### 2.2 已确认根因

- 系统提示词已正常传入模型，并非提示词丢失或未生效。
- 用户输入“你是谁”本身不会被输入分类器识别为政策事实问题，也不会直接触发强制检索。
- 模型依据系统提示词生成人设回答时，可能使用“社保政策”“相关规定”等自然表达。
- 输出正则会把部分人设或能力说明误判为政策事实；例如“我的职责是帮助您理解社保政策和相关规定”会进入来源门禁。
- 该轮没有调用 `searchPolicy` 时不存在可信命中，后处理因此把模型原始回答整段替换为：

  ```text
  未在官方原文库中检索到可靠依据，无法提供政策事实或来源链接。请咨询12333或当地社保窗口。
  ```

- 既有能力自述豁免依赖固定措辞，无法可靠覆盖 LLM 的同义表达，继续扩充正则只能缓解个别样例，不能消除架构性误判。

### 2.3 产品问题

当前实现让服务端正则同时承担意图分类、工具路由和最终回答裁决。其结果是：

- 普通对话可能被错误导向知识库检索或被兜底语覆盖；
- 系统提示词定义的角色和对话策略无法稳定呈现给用户；
- LLM 已具备的工具选择能力被首步强制调用替代；
- 新增自然语言表达时需要持续扩充正则白名单，维护成本高且无法证明完备性；
- 模型原始文本在输出前被整体缓存，非政策对话也可能失去正常的流式体验。

## 3. 目标与非目标

### 3.1 目标

1. 恢复系统提示词对角色、对话策略和工具使用原则的权威性。
2. 将知识库检索作为普通 Tool 提供，由 LLM 根据当前问题和上下文自主决定是否调用。
3. 取消服务端基于自然语言正则的强制检索和完整回答替换。
4. 保留 `searchPolicy` 工具边界内已有的输入、上下文和来源真实性校验。
5. 保持多步工具循环、流式回答、工具消息展示和会话持久化正常。
6. 删除系统提示词中写死的动态政策事实，避免旧数据诱导模型绕过检索。

### 3.2 非目标

- 不修改 Agent 内部 RAG 搜索或原件读取 API。
- 不修改 PostgreSQL、MinIO、Embedding、Rerank、索引版本或已有知识库数据。
- 不修改 `computePlan`、`validateField`、`updateProfile` 的业务语义。
- 不新增独立意图分类模型、规则路由器或第二次 LLM 审核调用。
- 不保证 LLM 在每一个政策问题上必然调用 `searchPolicy`。
- 不以新的关键词正则、白名单或黑名单替代现有门禁。
- 不包含生产部署、政策发布、数据迁移或案例库改写。

## 4. 用户与使用场景

### 4.1 目标用户

- 希望了解助手身份、能力和使用方式的登录用户；
- 通过多轮对话补充个人社保画像的用户；
- 需要当前或地区性政策依据、官网原文和归档原件的用户；
- 使用规划计算能力并需要工具结果解释的用户。

### 4.2 用户故事

- 作为用户，当我询问“你是谁”时，我希望获得系统定义的“社保规划助手”身份说明，而不是知识库无命中提示。
- 作为用户，当我寒暄、询问能力或补充个人信息时，我希望助手自然回答，不产生无关检索。
- 作为用户，当我询问当前或地区性的政策事实时，我希望助手能自行判断是否需要查询官方原文，并在查询后基于真实结果回答。
- 作为用户，当官方原文库没有可靠命中或检索服务不可用时，我希望助手诚实说明限制，而不是编造政策或来源。

## 5. 目标问答链路

目标链路为：

```text
Chat API
  → 用户鉴权、请求校验、会话读取与确认地区注入
  → UI 消息转换为模型消息
  → 拼接 SYSTEM_PROMPT、用户画像、未决问题和服务器日期
  → 向 LLM 注册全部工具，toolChoice = auto
  → LLM 根据系统提示词、工具描述和会话上下文决定是否调用工具
  → 工具执行并在各自边界内校验输入与输出
  → 工具结果返回 LLM，允许继续多步推理和工具调用
  → LLM 生成最终回答
  → 回答原样流式返回并持久化
```

服务端继续负责鉴权、会话所有权、地区上下文、工具执行安全和数据持久化，但不再通过自然语言正则裁决用户意图或改写最终回答。

## 6. 功能需求

### ATR-FR-001 系统提示词权威性

系统提示词必须继续定义“社保规划助手”角色、支持范围、画像累积、地区确认、规划计算和工具使用原则。身份介绍、能力说明及普通交互必须能够直接依据系统提示词生成。

系统提示词必须明确区分不同内容的权威来源：

- 用户事实来自当前用户消息及已确认的用户画像；
- 退休节点、缴费缺口、成本、方案对比等规划计算数值来自 `computePlan`；
- 当前、地区性或需要官方依据的政策事实及其金额、比例、资格、期限、有效期和文件依据来自 `searchPolicy`；
- 非政策内容可以使用系统提示词、用户上下文及其他工具的合法结果。

同一轮对话可以组合多类来源，但每类内容不得越过上述来源边界。

### ATR-FR-002 自动工具选择

`searchPolicy` 必须与 `computePlan`、`validateField`、`updateProfile` 一同作为普通工具注册给模型。对话编排必须显式使用 `toolChoice: "auto"`，不得在单独步骤覆盖为强制 `searchPolicy`。

### ATR-FR-003 禁止输入正则强制检索

服务端不得根据用户消息中的“社保”“政策”“金额”“比例”“期限”等关键词决定是否强制调用 `searchPolicy`。必须移除现有输入政策事实分类及其 `prepareStep` 强制工具选择链路。

### ATR-FR-004 禁止输出正则整段替换

服务端不得根据模型输出中的关键词判断其是否为政策事实，也不得因缺少 `searchPolicy` 命中或双来源链接而把完整回答替换为固定兜底语。必须移除输出政策事实分类、文本缓存、来源放行判断和整段替换链路。

### ATR-FR-005 普通对话直接回答

身份介绍、寒暄、能力说明、服务边界说明、画像收集、画像回显及其他无需外部事实依据的交流应由 LLM 直接回答。此类对话不应仅因包含“社保”“政策”或“规定”等领域词语而调用知识库。

### ATR-FR-006 LLM 自主判断检索需要

当回答依赖当前、地区性、时效性或需要官方原文支持的政策事实时，系统提示词和工具描述应引导 LLM 调用 `searchPolicy`。典型场景包括政策金额、比例、资格、期限、有效期、文件依据及政策来源。

该要求属于模型行为指令，不得在服务端重新实现为关键词分类器或隐藏的强制路由。

### ATR-FR-007 工具结果使用约束

LLM 调用 `searchPolicy` 后：

- 最终回复中的政策事实部分必须以 `searchPolicy` 实际返回内容为唯一依据；
- 有可靠命中时可引用返回的发布机关、文件标题、官网原文和归档原件路径；
- 空命中时应说明官方原文库暂未检索到可靠依据；
- 工具失败时应说明检索暂时不可用；
- 不得编造工具未返回的文号、链接、机关或归档路径。

该限制不排除同一轮使用其他合法来源：规划计算数值可以使用 `computePlan`，用户事实可以使用当前消息和已确认画像，画像更新可以使用 `updateProfile`。不得把“政策事实只使用检索结果”扩大解释为“整轮回答只能包含检索结果”。

这些约束通过系统提示词、工具描述、测试和评测落实，不通过服务端最终文本正则实现。

### ATR-FR-008 保留工具边界校验

`searchPolicy` 工具必须保留以下现有校验：

- 请求地区等于会话已确认地区；
- `as_of_date` 等于 Chat Route 单次注入的服务器日期；
- Query、日期、地区代码和 `top_k` 的 Schema 校验；
- 命中文档版本 ID、标题、机关、MIME、分数和内容哈希校验；
- 官网地址必须是 HTTPS `gov.cn` 或其子域名；
- 归档路径只能根据已校验的文档版本 ID 在 Web 层构造；
- 内部服务错误、鉴权失败、对象缺失或来源结构异常继续失败关闭。

### ATR-FR-009 移除静态政策事实

系统提示词中的“2025 政策要点”及其退休年龄、最低缴费年限、医保年限、灵活就业费率和补贴数字必须删除。动态政策事实不得继续以静态提示词内容提供给模型。

必须移除的静态政策内容还包括：

- 固定政策文件名称及其发布日期、生效日期；
- 固定年度或月份调整规则；
- 退休年龄、缴费年限、金额、比例、资格期限和补贴期限等具体政策值；
- 用户画像展示标签中附带的政策年龄解释，例如“50 岁退休”“55 岁退休”。

允许保留的数字包括：用户输入与字段识别示例、行政区划代码、工具参数范围、执行步骤上限、服务渠道号码以及不表达政策结论的响应格式数字。画像枚举可以保留，但展示给模型的标签不得附带未经当轮工具结果支持的政策年龄。

角色、交互流程、字段识别、地区确认和工具使用规则不属于动态政策事实，应继续保留。

本条的范围边界：仅约束系统提示词、注入模型的动态上下文（画像标签等）和工具描述。以下位置不属于本条范围，按后续 Work Item 单独处理，不作为本 Feature 的验收对象：首页营销文案与对话工具结果卡片中的"4050"俗称（`src/app/(client)/page.tsx`、`src/components/chat/ToolResultCard.tsx`）、规则引擎场景构建器场景标签中的年龄表述（`src/lib/engine/scenario-builder.ts`，由物化政策参数驱动）。

### ATR-FR-010 保持消息与工具循环

移除来源后处理后必须保持：

- Vercel AI SDK 多步工具调用上限和工具执行上下文；
- DeepSeek Chat Completions 工具循环兼容；
- 工具调用及工具结果消息正常进入 UI 流；
- 文本按正常模型流输出，不再等待来源门禁缓存完整回答；
- 用户输入快照和最终 Assistant 消息继续按现有会话所有权持久化；
- 流式中断继续使用现有错误处理，不得留下越权会话或跨用户数据。

## 7. 系统提示词要求

系统提示词至少应清晰表达以下规则：

1. 你是“社保规划助手”，负责帮助用户理解社保情况并制定规划方案。
2. 身份介绍、寒暄、能力说明、服务边界和用户画像交流可直接回答，不需要调用政策检索。
3. 当问题需要当前、地区性或可引用的官方政策依据时，自主调用 `searchPolicy`。
4. 调用 `searchPolicy` 时，地区代码必须使用会话已确认地区，日期必须使用服务端注入日期。
5. 规划计算中的退休节点、缴费缺口、成本和方案数字仅使用 `computePlan`；不得由模型自行计算。
6. 当前或地区性政策中的金额、比例、资格、期限、有效期和文件依据仅使用 `searchPolicy`；不得凭记忆补充。
7. 用户自述和画像信息可以使用用户消息、已确认画像及 `updateProfile` 结果。
8. 同一轮使用多个工具时，分别按上述来源边界组织回答；`searchPolicy` 的限制只约束政策事实部分，不排除合法的画像和规划结果。
9. `searchPolicy` 有命中时仅使用其返回的政策事实和来源；空命中或失败时如实说明，不得编造。
10. 不在系统提示词中保存可能随时间变化的具体政策文件、日期、调整规则、金额、比例、年龄、年限或补贴值。

工具描述与系统提示词的职责应一致：系统提示词描述判断原则和回答责任，工具描述说明工具适用场景、输入约束与返回能力。

## 8. 数据、接口与权限边界

### 8.1 接口

以下接口及其请求、响应格式保持不变：

- `POST /api/chat`；
- Agent 内部 `POST /internal/v1/rag/search`；
- Agent 内部原件读取接口；
- Web 登录态原件下载代理；
- `searchPolicy({ query, jurisdiction_code, as_of_date, top_k })`。

本 Feature 只改变 Chat Agent 如何选择工具以及最终文本是否经过来源后处理。

### 8.2 数据

本 Feature 不新增或修改数据库表、迁移、RAG 数据、对象键、Embedding、检索审计结构或案例库内容。

正常调用 `searchPolicy` 时，现有检索审计行为保持不变；未调用时不得为了模拟门禁而写入检索审计。

### 8.3 权限与安全

- 用户必须继续通过 Chat API 鉴权。
- 会话读取、更新和原件下载必须继续校验用户所有权。
- Next 到 Agent 的调用继续使用短期服务 JWT。
- 不得向模型、浏览器或日志暴露 MinIO 内部地址、访问凭据、API Key 或服务 JWT。
- 不得记录完整用户消息或完整模型回答用于工具路由判断。

## 9. 非功能需求

### ATR-NFR-001 日志与隐私

删除语义门禁不得引入记录完整用户消息、完整模型回答、JWT、API Key、MinIO 凭据或其他敏感信息的新日志。现有请求 ID、会话 ID、步数、Token 用量和错误类型日志可保留。

### ATR-NFR-002 RAG 与数据兼容

不得修改 RAG API、数据库、MinIO、索引、原件下载接口、政策发布状态或持久案例数据。现有 `searchPolicy` Schema 和结果类型保持兼容。

### ATR-NFR-003 Provider 兼容

DeepSeek 对携带非空 Tools 的 Chat Completions 请求继续使用既有兼容处理，首步和后续步骤均不得因缺失 `reasoning_content` 或 Thinking 模式与工具选择冲突而失败。

## 10. 失败模式与产品取舍

| 场景 | 目标行为 |
| --- | --- |
| LLM 判断无需检索 | 直接回答，服务端不改写 |
| LLM 对政策问题未调用检索 | 服务端不改写；这是自主工具模式已接受的取舍 |
| `searchPolicy` 返回空命中 | LLM 说明缺少可靠依据，不生成来源链接 |
| `searchPolicy` 暂时不可用 | LLM 说明检索不可用并建议稍后重试或咨询官方渠道 |
| 地区尚未确认 | 工具返回 `JURISDICTION_REQUIRED`，LLM 引导用户确认地区 |
| 地区或日期与服务端上下文不一致 | 工具拒绝请求，LLM 不得绕过校验 |
| 工具返回来源结构异常 | 工具失败关闭，不把异常来源交给模型作为可信依据 |
| 同轮使用画像、`computePlan` 和 `searchPolicy` | 分别使用用户/画像、规划工具和检索工具的合法结果；不得因政策来源约束丢弃画像或规划结果 |
| LLM 生成未经工具支持的政策事实 | 不再由服务端正则拦截；由提示词、模型选择和评测约束 |
| LLM 在工具命中后生成额外链接 | 不再做最终文本正则替换；属于模型质量与评测问题 |
| 模型流中断 | 保持现有流错误提示和输入快照持久化 |

自主工具模式明确接受：移除服务端语义门禁后，系统不再对所有可能的政策幻觉提供确定性拦截。不得以未公开的关键词规则重新引入该门禁。

## 11. 修复计划

1. 从 `ATR-FR-001`～`ATR-FR-010` 派生最小回归测试，首先复现“你是谁”的原始角色回答被知识库兜底语覆盖。
2. 新增工具选择契约，证明全部工具可用且 `toolChoice` 为 `auto`，不存在首步强制 `searchPolicy`。
3. 删除输入政策事实正则、首步强制工具选择、输出政策事实正则、来源文本缓存、双链放行判断和固定兜底替换。
4. 调整系统提示词和 `searchPolicy` 工具描述，明确由 LLM 自主判断，并删除静态“2025 政策要点”。
5. 消除 `computePlan` 与 `searchPolicy` 的数值来源冲突，明确政策事实限制不排除同轮使用用户画像和其他工具结果。

## 13. 验收场景

### ATR-AC-001 身份回答

已登录用户在新会话或已有会话中输入“你是谁”。模型返回系统提示词定义的“社保规划助手”身份和能力说明；本轮不调用 `searchPolicy`，回答中不出现固定知识库兜底语。

### ATR-AC-002 普通交流

分别验证用户寒暄、询问助手能力和补充画像三个场景。寒暄与能力询问由模型直接回答且不调用 `searchPolicy`；画像场景可以按既有规则调用 `updateProfile`，但不得调用 `searchPolicy`。任何场景都不得仅因回答含“社保”“政策”“规定”等领域词语而被服务端重写。

### ATR-AC-003 自动工具选择

对话请求向模型提供全部工具且 `toolChoice=auto`。代码中不存在根据消息内容把首步改为强制 `searchPolicy` 的配置。

### ATR-AC-004 自主政策检索

Mock LLM 面对当前地区政策事实问题时自主调用 `searchPolicy`。工具使用会话确认地区和服务器日期，命中后最终回答使用工具返回的真实发布机关、标题、官网地址和归档路径。混合工具场景中，用户画像、`computePlan` 规划数值和 `searchPolicy` 政策依据必须同时保留，并分别遵守各自来源边界。

### ATR-AC-005 空命中与不可用

分别验证工具返回空命中和工具不可用两个完整模型循环。模型必须如实说明限制，最终回答不得包含伪造官网、文号或归档路径；工具不可用不得只以工具函数单测代替模型消费失败结果的验收。

### ATR-AC-006 无隐藏来源门禁

实现中不存在用户政策语义正则、输出政策语义正则、政策文本缓存、来源双链放行函数或固定兜底整段替换。服务端不对未检索回答进行隐藏改写。

### ATR-AC-007 多步与持久化回归

`computePlan`、`updateProfile`、`validateField` 和 `searchPolicy` 仍可参与多步工具循环。最终 Assistant 文本正常流式展示、保存并在刷新后恢复。

### ATR-AC-008 项目门禁

AI 聚焦测试、完整 Node 测试、TypeScript、ESLint、生产 Build 和 Chromium 对话 E2E 全部通过，最终提交范围的 `git diff --check` 退出 0，且没有通过降低测试、来源校验或安全边界获得通过结果。
